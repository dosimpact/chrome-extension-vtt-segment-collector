# VTT Collector 구현 문서

## 개요

이 프로젝트는 활성 탭에서 내려오는 분절된 `VTT` 자막을 수집해서 크롬 확장 프로그램 팝업 안에서 누적 표시하고, `TXT`/`VTT`로 다운로드하거나 전체 복사할 수 있게 만드는 MV3 기반 크롬 익스텐션이다.

기술 스택은 다음과 같다.

- `React + TypeScript + Vite`
- `Manifest V3`
- `pnpm`
- 팝업 UI: `Tailwind CSS + Radix UI primitives + shadcn 스타일 컴포넌트`

## 현재 구현 범위

현재까지 구현된 기능은 다음과 같다.

- 활성 탭 기준 자막 세그먼트 수집
- `.vtt` URL 기반 자막 수집
- `data:` URL인데 디코드 결과가 `WEBVTT`인 경우 수집
- `m4s/mp4` 계열 미디어 세그먼트 제외
- 분절된 `VTT` cue 병합
- 중복 cue 제거
- 팝업에서 누적 자막 실시간 확인
- 페이지 URL 단위 자막 저장 및 재사용
- `Auto detect subtitles` 기본 활성화
- `Auto save captions by URL` 기본 활성화
- `Clear Captions`
- `Download VTT`
- `Download TXT`
- `Copy All Captions`

## 아키텍처

구성은 다음 네 부분으로 나뉜다.

- `page-script`
  페이지 컨텍스트에서 `fetch`/`XMLHttpRequest`를 후킹한다.
- `content script`
  page script에서 넘어온 메시지를 확장 백그라운드로 전달한다.
- `background service worker`
  세션 상태를 유지하고 자막 누적, URL 저장소 관리, 다운로드 처리, `chrome.debugger` 네트워크 캡처를 담당한다.
- `popup`
  현재 탭 세션 상태와 URL 저장 라이브러리를 조회해서 `Live / Library / Settings` UI를 보여준다.

## 수집 조건

v1 기준 수집 조건은 단순하다.

- URL에 `.vtt`가 포함되고 본문이 `WEBVTT`로 확인되면 수집
- `data:` URL인데 디코드 후 `WEBVTT`면 수집
- `.m4s`, `.mp4`, `styp/moof/mdat` 시그니처는 제외

또한 v1에서는 트랙 개념을 버리고, 같은 탭에서 들어오는 모든 유효한 `VTT` cue를 단일 버퍼로 합친다.

추가로 현재 구현에서는 페이지 URL 단위로 저장소를 운영한다.

- 현재 탭의 페이지 URL이 같으면 기존 자막을 preload
- 이후 새로 들어오는 세그먼트와 기존 cue를 다시 머지
- 머지 규칙은 동일하게 중복 제거 + 시간순 정렬 유지

## 팝업 기능

팝업에서는 다음 기능을 제공한다.

- `Live` 탭
  - 현재 상태 표시
  - 자동 감지 on/off
  - 감지 시작/중지
  - 지금까지 모은 자막 전체 보기
  - 지금까지 모은 자막 제거
  - 지금까지 모은 자막 전체 복사
  - 지금까지 모은 자막 다운로드 `TXT`
  - 지금까지 모은 자막 다운로드 `VTT`
- `Library` 탭
  - URL 단위 저장 자막 목록 보기
  - 저장 자막 다운로드 `TXT`
  - 저장 자막 다운로드 `VTT`
  - 저장 자막 삭제
- `Settings` 탭
  - `Auto save captions by URL` on/off

## 시행착오 및 트러블슈팅

### 1. 왜 처음에는 감지가 안 되었는가?

처음 구현은 페이지 컨텍스트에서 `fetch`/`XHR`를 후킹해서 자막 응답 본문을 읽는 방식이었다. 그런데 실제 서비스는 자막이 항상 단순한 `.vtt` 텍스트 응답으로만 내려오지 않았다.

문제가 되었던 패턴은 다음과 같다.

- `seg-xxx_init.vtt` 요청은 존재하지만
- 플레이어 내부에서 `arraybuffer`로 읽거나
- `data:application/octet-stream;base64,...` 형태로 다시 소비하거나
- 일부 요청은 page hook만으로는 안정적으로 추적되지 않았다

이 때문에 “Network 탭에는 보이는데 확장에서는 못 잡는” 현상이 발생했다.

### 2. 왜 크롬 디버깅이 필요했는가?

`chrome.debugger`가 필요했던 이유는 **페이지 후킹만으로는 실제 네트워크 응답 바디를 항상 안정적으로 확보할 수 없었기 때문**이다.

구체적으로는 다음 문제들이 있었다.

- 플레이어가 `XMLHttpRequest`를 `responseType = 'arraybuffer'`로 사용함
- 자막 본문이 page script에서 읽히긴 하지만, 사이트 구현에 따라 타이밍이나 전달 경로가 달라짐
- 어떤 응답은 페이지 레벨 후킹보다 브라우저 네트워크 레벨에서 보는 쪽이 더 확실함
- 디버깅 시 “응답이 실제로 도착했는지”, “본문이 비어 있는지”, “필터에서 제외됐는지”를 정확히 확인할 필요가 있었음

즉, `chrome.debugger`는 단순히 “고급 기능”이라서 쓴 게 아니라, 아래를 명확히 하기 위해 필요했다.

- 실제 응답이 왔는가
- 응답 바디를 읽을 수 있는가
- base64 인코딩 여부는 무엇인가
- 필터링 단계에서 왜 통과/제외되는가

결론적으로 이 프로젝트에서는:

- page hook은 빠른 수집 경로
- `chrome.debugger`는 브라우저 네트워크 레벨 검증 및 보강 경로

로 쓰는 것이 가장 실용적이었다.

### 3. 왜 깨진 한글 자막이 같이 보였는가?

정상 자막과 `ê·¸...` 같은 깨진 자막이 동시에 보인 이유는 동일한 자막이 두 경로로 들어왔기 때문이다.

- 하나는 UTF-8이 올바르게 디코드된 자막
- 다른 하나는 debugger 응답의 base64 body를 잘못 처리한 자막

처음에는 debugger 경로에서 base64 body를 `atob()` 문자열로만 처리해서 UTF-8 한글이 mojibake로 깨졌다. 이 경우 cue text가 달라지기 때문에 중복 제거 키도 달라져서 둘 다 남았다.

해결은 debugger body를 `TextDecoder` 기반 UTF-8로 복원하는 방식으로 바꾼 것이다.

### 4. 왜 자막이 수집됐는데 팝업에서는 안 보였는가?

초기 구조는 “트랙 감지”와 “트랙 선택 후 누적”이 분리돼 있었다. 그래서 자막 세그먼트가 실제로 들어와도 사용자가 트랙을 선택하지 않으면 팝업에는 비어 있는 것처럼 보였다.

v1에서는 이 구조를 버리고, 현재 탭에서 유효한 `VTT` cue가 들어오면 모두 단일 버퍼에 누적되게 바꿨다.

### 5. 왜 `Auto detect subtitles` 기본값을 켜야 했는가?

실제 사이트는 페이지 진입 직후 자막 세그먼트를 프리패칭하는 경우가 많았다. 이때 사용자가 팝업을 열고 `Start Detection`을 누를 때까지 기다리면 이미 첫 자막 세그먼트를 놓치게 된다.

그래서 v1에서는 기본값을 `true`로 바꾸고, 저장소에도 기본 `true`를 기록하도록 바꿨다.

### 6. 왜 다운로드가 안 되었는가?

초기 다운로드 구현은 background service worker에서 `Blob`을 만들고 `URL.createObjectURL()`을 통해 다운로드 URL을 생성했다. 그런데 MV3 service worker 환경에서는 이 URL이 다운로드 시점에 안정적이지 않을 수 있다.

해결은 blob URL 대신 UTF-8 `data:` URL을 직접 만들어 `chrome.downloads.download()`에 넘기는 방식으로 바꾼 것이다.

### 7. 왜 `Copy All` 기능을 popup에서 직접 처리했는가?

복사는 background로 왕복할 필요가 없다. popup은 이미 현재 세션의 누적 cue를 들고 있고, 복사 대상 문자열도 `TXT` 포맷 기준으로 바로 만들 수 있다.

따라서 다음 이유로 popup에서 직접 처리했다.

- 구조가 단순함
- 반응 속도가 빠름
  - 불필요한 runtime message를 줄일 수 있음
  - 클립보드 실패 시 fallback을 popup DOM에서 바로 처리 가능함

### 8. 왜 자막 저장 단위를 세그먼트 URL이 아니라 페이지 URL로 잡았는가?

세그먼트 URL은 영상 재생 중 계속 바뀌고, 사용자가 다시 보고 싶은 대상도 보통 “현재 보고 있는 페이지의 자막”이다. 따라서 저장 키를 세그먼트 URL로 잡으면 재사용 가치가 낮고, 동일 콘텐츠라도 여러 레코드로 쪼개질 수 있다.

반면 페이지 URL 기준 저장은 아래 장점이 있다.

- 같은 페이지를 다시 열면 기존 자막을 즉시 preload 가능
- 새로 들어오는 세그먼트와 자연스럽게 머지 가능
- 팝업 라이브러리에서 사용자가 이해하기 쉬움

## 구현하면서 얻은 교훈

이번 구현에서 중요한 교훈은 다음과 같다.

- “Network 탭에 보인다”와 “확장에서 안정적으로 읽을 수 있다”는 다른 문제다.
- 멀티 레이어 시스템에서는 page, content, background 각각에서 어디까지 성공했는지 로그를 넣어야 원인을 좁힐 수 있다.
- 트랙 개념처럼 확장 가능한 설계가 v1에서는 오히려 복잡도를 높일 수 있다.
- 한글 자막처럼 문자 인코딩 민감도가 높은 데이터는 base64 처리 경로를 반드시 별도 검증해야 한다.

## 컨텍스트 엔지니어링 피드백

이번 작업을 더 적은 시행착오로 한 번에 구현하려면, 처음 요구사항에 아래 정보가 같이 포함됐으면 훨씬 빨랐을 것이다.

### 1. 실제 자막 네트워크 샘플을 처음부터 제공

특히 아래 정보가 초반에 있으면 좋았다.

- 실제 `.vtt` URL 예시
- `data:application/octet-stream;base64,...` 예시
- `responseType: arraybuffer` 여부
- `content-type: application/octet-stream` 여부

이 정보가 초기에 있었다면:

- `.vtt` 확장자 필터만으로 충분하다고 착각하지 않았고
- 인코딩 문제와 debugger 보강 필요성을 더 빨리 판단할 수 있었다.

### 2. v1 범위를 더 일찍 강하게 고정

예를 들면 처음부터 이렇게 주면 좋았다.

- “트랙 선택 기능은 필요 없다”
- “같은 탭의 모든 VTT를 하나로 모아도 된다”
- “m4s는 무시해도 된다”
- “popup만 필요하고 overlay는 필요 없다”

이렇게 되면 불필요한 확장 가능성 설계를 초기에 덜 하게 된다.

### 3. 성공 기준을 UI 기준으로 명확히 제시

예를 들어 아래처럼 주면 좋았다.

- “페이지 진입 직후 자막 프리패치를 놓치면 안 된다”
- “팝업을 열었을 때 바로 누적 자막이 보여야 한다”
- “내가 원하는 최종 액션은 보기, 복사, txt/vtt 다운로드다”

이렇게 표현하면 `Auto detect` 기본값이나 popup polling 같은 결정이 더 빨리 나온다.

### 4. 디버깅 시 기대 로그를 미리 명시

예를 들어 아래처럼 말해주면 좋다.

- “page script에서 `WEBVTT`가 보이면 성공”
- “background에서 `session updated`와 `cueCount` 증가를 보고 싶다”
- “실패 시 service worker 로그 기준으로 판단하자”

이렇게 되면 디버깅 대화의 왕복 횟수가 줄어든다.

### 5. 구현 요청 템플릿 예시

앞으로 비슷한 작업을 요청할 때는 아래처럼 쓰면 훨씬 강하다.

1. 최종 목표
   활성 탭에서 분절된 `VTT` 자막을 모아서 popup에서 보여주고, 전체 복사/다운로드까지 가능하게 한다.

2. v1 범위
   - `.vtt`와 `WEBVTT data:`만 지원
   - `m4s` 무시
   - 트랙 분리 없음
   - popup만 사용

3. 실제 입력 예시
   - 자막 URL 샘플
   - base64 data URL 샘플
   - DevTools 콘솔/네트워크 로그 샘플

4. 성공 조건
   - 페이지 첫 로드 프리패치도 놓치지 않음
   - 팝업에서 누적 자막이 바로 보임
   - `Clear`, `Copy`, `TXT`, `VTT` 동작

5. 비기능 요구사항
   - 콘솔 에러는 페이지 Sentry로 보고되지 않게 최대한 방지
   - 디버그 로그는 `>>` prefix 사용

이 정도만 초기 컨텍스트에 들어가도 구현 정확도와 속도가 눈에 띄게 좋아진다.

## 현재 상태 요약

현재 기준으로 프로젝트는 다음 상태다.

- segmented `VTT` 수집 가능
- popup에서 누적 자막 확인 가능
- 한글 인코딩 문제 보정 완료
- 다운로드 가능
- 전체 복사 가능
- 자동 감지 기본 활성화
- popup UI 리디자인 완료
